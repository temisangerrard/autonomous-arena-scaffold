# LLM Brief For VC Applications

Use this prompt with any LLM to generate a VC application draft.

---

You are helping me write a high-quality startup VC application.

## Company / Product Context

We are building **Autonomous Agent Betting Arena**: a multiplayer game economy on Base where players can:
- Play games directly against the house or other players
- Fund bot wallets and let autonomous bots play in the arena

### What is live now
- Multiplayer shared world with real-time presence
- Onchain escrow settlement using a pari-mutuel pool model on Base
- 5 live game experiences:
  1) Coinflip
  2) Rock Paper Scissors
  3) Dice Duel
  4) BTC prediction (5-minute round)
  5) BTC prediction (24-hour round)
- Admin stack for treasury, contracts, users, markets, and runtime operations
- Treasury UX includes controlled wallet operations, internal transfers, external withdraw, and house treasury controls

### Product direction
End state is a persistent arena where users can choose:
- Manual play
- Autonomous bot play
- Hybrid play

with wallet-native, transparent onchain settlement and operator-grade controls.

## Writing Goals

Write this VC application in a way that is:
- Specific and concrete
- Technically credible
- Ambitious but not hypey
- Focused on why this can become a large business

Avoid generic startup language and avoid fluff.

## Required Output Structure

1. `One-line company description` (max 25 words)
2. `Problem` (what is broken today)
3. `Solution` (what we built)
4. `Why now`
5. `Product today` (what actually works now)
6. `What changes at scale` (network effects / defensibility)
7. `Business model`
8. `Go-to-market`
9. `Competition and differentiation`
10. `Traction` (if metric unknown, mark as `TBD` and suggest exact metric to collect)
11. `Moat` (technical + distribution)
12. `Roadmap (next 12 months)`
13. `Risks and mitigations`
14. `The ask` (fundraise amount, use of funds, milestones)

## Style Constraints

- Keep it concise and hard-hitting.
- Use plain English.
- No buzzword stacking.
- Every claim should be testable.
- If data is missing, output:
  - `Assumption: ...`
  - `Metric to collect: ...`

## Founder Input Placeholders (fill these before finalizing)

- Team background: `<ADD>`
- Current traction numbers: `<ADD>`
- Revenue / volume / retention: `<ADD>`
- Fundraise target: `<ADD>`
- Geography focus: `<ADD>`
- Top 3 milestones from this raise: `<ADD>`

Now produce:
1) a polished full application draft
2) a tighter "partner forward" version (40% shorter)
3) a 150-word cold intro message for a VC partner.
